# NEBULAB コーポレートサイト リニューアル 作業指示書 v2

対象: nebulab.jp
作成日: 2026-09-03（v2。v1 のダークトーン案は破棄）
関連: `nrt-loft-renewal-spec.md`（姉妹サイト NRT LOFT のリニューアル指示書）

## 0. v1 からの変更点

デザインの方向を**ダークトーンから明るいライトテーマへ変更**した。
検討の結果、以下の理由でライトを採用した。

- ダークは目に優しいが、コーポレートサイトとしての体裁が出にくい
- 成田の線画を背景の主役にしていたが、**事業（受託開発・SES）と成田の
  関連はそこまで強くない**。地域性を前面に押すより、デザインとして
  成立させることを優先する
- 写真素材（暗所撮影）の要求水準が高く、着手の障害になる

したがって v1 の Phase 2（デザイン基盤）と Phase 3（トップページ）の
配色・装飾に関する記述はすべて無効。本書の内容に従うこと。

**Phase 1（誤情報の削除）は既に完了している。** 再実施は不要。

## 1. 背景と目的

NRT LOFT を「AIでものづくりを発信するメディア」として切り出したことに伴い、
NEBULAB 側を**会社としての顔**に整理し直す。

あわせてデザインを刷新する。旧サイトは画像・写真が乏しく、コピーと
サービス説明だけで構成されていたため、内容が抽象的で、どの開発会社にも
当てはまる見た目になっていた。これを脱する。

### 読者の優先順位

1. **法人の開発案件を検討している人**（受託・SES・内製化支援）
2. **NRT LOFT から流れてくる「本格的に作りたい」人**
3. 成田の地域事業者（IT相談）

旧サイトは 3 が主導線だった。**1と2を主役に、3は残すが主役から降ろす。**
地域事業者向けの入口は削除しない。

## 3. Phase 2 — デザイン基盤

### 3.1 方向性

**コズミックラテの地に、筆で描いたような有機的なストロークを重ねる。**

基調色はコズミックラテ `#FFF8E7`。宇宙全体の光を平均した色で、
社名 NEBULAB（星雲）と由来を共有する。

背景装飾は水彩・油彩の筆のストローク。色は実際の散光星雲の色から取る。
デジタルなグリッチやノイズではなく、**滲み・かすれ・透明な重なりのある
有機的な質感**にする。

**色は自由でも、レイアウトは極めて硬く整える。** 派手な色に対する
釣り合いをレイアウトの規律で取る。これが崩れると、色だけ派手な
素人サイトになる。

- 文字は左揃えで統一
- セクションのラベルは小さな英字＋短い下線
- すべてのリンクとボタンを同じ形にする
- グリッドを崩さない
- 余白を大きく取る

### 3.2 カラートークン

| 用途 | 値 |
|---|---|
| 基調（背景） | `#FFF8E7` |
| カード面 | `#FFFDF7` |
| 罫線 | `#E5DFCE` |
| 本文 | `#1C1A17` |
| 補助テキスト | `#6B655C` |
| UIアクセント（ボタン・リンク） | `#2F3A8C` |

**UIアクセントは `#2F3A8C` の1色のみ。** ボタン、リンク、フォーカスリング、
アクティブ状態はすべてこの色。他の色をUIに使わない。

### 3.3 筆のストロークの色

| 色 | 値 |
|---|---|
| ピンク | `#C6478A` |
| 藍 | `#2F3A8C` |
| 青緑 | `#2E8F8A` |
| 琥珀 | `#E0912F` |

**この4色は装飾専用。** 文字色・ボタン・アイコンには使わない。

### 3.4 筆の配置ルール

**これが最重要。守られないとデザインが破綻する。**

- **本文が乗る面には筆を置かない。** 文字の可読性を最優先する
- 筆は**セクションの境界と、ヒーロー・NRT LOFT ブロックに限定**する
- 全面に敷き詰めない。基調色の上に薄く重ねる
- ストロークは横方向に流れる帯として配置し、**画面の左右に抜けさせて
  断ち切りにする**。枠内に収めると挿絵になる
- カードやテキストブロックの背後に回り込ませない

### 3.5 ライトテーマのみ

ダークモードは実装しない。NEBULAB と NRT LOFT はどちらもライトだが、
差別化は筆のストローク・藍のアクセント・硬いレイアウトで行う。
（NRT LOFT は手書き系フォントと黄色のマーカー、紙色 `#F7F6F1`）

### 3.6 タイポグラフィ

- 日本語見出し: 細めのゴシック。大きくしすぎず、字間を広めに
- 英字: グロテスク系サンセリフ。小さく、字間を広く
- セクションラベルは小さな英字＋短い下線（`SELF PRODUCTS` `SERVICES` など）
- 見出しと本文のサイズ差を過度に付けない

## 4. Phase 2b — 動きの仕様

### 4.1 原則

**動かすのは背景の筆のストロークのみ。**
テキスト、カード、端末画像、写真は一切動かさない。

カードやテキストにフェードインを付けると、読もうとした瞬間に文字が動くため
かえって読みづらくなる。筆は背景装飾なので、動いても情報の読み取りを妨げない。

### 4.2 パララックス（ヒーロー / NRT LOFT ブロックの2箇所のみ）

スクロール量に対して筆のレイヤーを `0.2〜0.35` 倍の速度で縦に移動させる。
複数のストロークがある場合はレイヤーごとに係数を変えて奥行きを出す
（手前 `0.35` / 中 `0.25` / 奥 `0.15`）。

実装要件:

- `IntersectionObserver` で対象が画面内にあるときだけ `requestAnimationFrame`
  を回し、`transform: translate3d(0, Ypx, 0)` を更新する
- `background-attachment: fixed` は iOS Safari で破綻するため**使わない**
- `scroll` イベントに直接ハンドラを付けず、rAF でスロットルする
- `will-change: transform` は動作中のみ付与し、終わったら外す

**構図上の注意:** パララックスで筆は上下に動くため、レイヤーは
セクションより **20〜30% 高く**作り、はみ出した分を `overflow: hidden` で切る。
ぴったりの高さで作ると、動いた瞬間に端が見える。

### 4.3 滲み出し（最大2箇所、初回のみ）

セクションが視界に入ったら、筆が左から右へ描かれる。
SVG パスの `stroke-dasharray` / `stroke-dashoffset` を使う。
duration 900ms 前後、ease-out。**一度だけ実行し、繰り返さない。**

### 4.4 禁止事項

- 常時ループするアニメーションを置かない
- カード・テキスト・見出しにフェードインを付けない
- スクロール量に応じて色を変えない
- ホバーで筆を動かさない

### 4.5 必須

- `prefers-reduced-motion: reduce` のとき、パララックスと滲み出しを
  完全に停止し、最終状態を表示する
- 動きが原因で CLS が発生しないこと

### 4.6 係数の調整

`0.2〜0.35` は出発点。実際はブラウザで見ながら詰める。
**「言われないと気づかないが、止めると物足りない」くらいが正解。**
実装後に確認を取ること。

## 5. Phase 3 — トップページ

### 5.1 ヘッダー

左にロゴ「NEBULAB」、中央にナビ（ABOUT / SERVICES / PRODUCTS / PARTNERS /
CONTACT）、右に問い合わせボタン（メールアイコン付き、`#2F3A8C` の塗り）。

### 5.2 ヒーロー

左にコピーとボタン2つ、右に自社プロダクトの画面を映した端末
（ノートPC・タブレット・スマートフォン）を斜めに重ねて配置。
背景に筆のストロークを大きく流し、左右に断ち切る。

コピーは**複数案を提示して確認を取ること。** 現時点の案:

```
小さなチームに、
大きな可能性をつくる。
```

発注者にとっての価値は「自分たちで作って運用しているので、
運用まで分かっている」という点にある。その趣旨が伝わる案も併せて出すこと。

### 5.3 自社プロダクト（SELF PRODUCTS）

カード4枚を横一列。各カードに画面キャプチャ、名前、1〜2行の説明、
そして**詳細ボタンと外部リンクボタン**。カード面は `#FFFDF7`、細い罫線。
下に「すべてのプロダクトを見る」。

**実在するプロダクトのみ掲載する。確定している3件:**

- Capture Box
- Navi
- みどりっこ

**4枚目は既存サイトの PROJECTS を調査して判断し、理由を添えて提案すること。**
候補は narita-guide.com / NAJIMI / SuperMindMap。
Nebula Place は構想段階のため除外する。

### 5.4 サービス（SERVICES）

4項目を横罫線で区切って縦に並べる。
左に細い番号 `01`〜`04`、中央に名前と説明、右に「詳細を見る」。
アイコンは使わない。

```
01  受託開発      業務システムやWebサービスの設計・開発・運用までワンストップで
02  内製化支援    技術力向上や開発プロセスの整備を通じて、チームの自走をサポート
03  自社プロダクト 自ら課題を見つけ、プロダクトを開発・運用。得た知見を還元
04  地域のIT支援  成田市を中心に、中小企業や地域団体のIT活用・DXを支援
```

**04「地域のIT支援」は必ず残す。** 順序を下げることで優先度を表現する。
デザインカンプでは「戦略的IT支援」に置き換わっていたが、これは誤り。

### 5.5 代表メッセージ（MESSAGE）

左に代表の写真、右に見出しと本文、末尾に役職と氏名。

**代表者名は既存サイトの `/about` から実際の表記を取得すること。**
カンプに含まれる氏名はすべて生成された架空のもの（§11 参照）。

写真が未用意の場合はプレースホルダを置く。

### 5.6 パートナー（PARTNERS）

**2社。** ロゴ枠＋社名＋2行程度の説明を横並び。
下に「すべてのパートナーを見る」。

```
MMPR合同会社
（事業内容は要確認）

株式会社AIM
https://ai-management.biz/
代表取締役 石井一之
生成AI活用の企業研修。初級者向けに、ChatGPTなどの生成AIを
業務にどう活かすかを、企業の課題に合わせて設計した研修として提供。
```

AIM との関係は以下の三層構造として説明できると望ましい。

```
NRT LOFT   一般向けにAIものづくりを発信
   ↓
AIM        法人向けに生成AI活用研修
   ↓
NEBULAB    本格的なシステム・サービス開発

### 5.7 NRT LOFT への導線

**この文面は生成AIに任せず、必ず以下をそのまま使うこと。**
デザインカンプでは3回連続でコワーキングスペースの説明に戻っており、
生成AIが旧サイトの情報を参照し続けている。

```

**画像も差し替える。** カンプのコワーキングスペース内装写真は使わない。
`public/decor/nrt-loft-building.png`（濃線の建物線画）を使う。

このブロックは筆のストロークを濃く入れて、印象を変える。

### 5.8 フッター

- 左に社名、短い説明文、SNSアイコン

**会社情報は既存サイトの実データを使うこと。** カンプの住所・電話番号・
法人格はすべて架空（§11 参照）。正しくは **Nebulab合同会社**（`LLC`。`Inc.` ではない）。

## 9. 品質基準

- モバイル対応必須
- **1024px 前後の中間幅で崩れないこと。** 実装後、1440px / 1024px /
  768px / 375px で表示を確認し、スクリーンショットで検証すること
- 見出しの折り返しは自動任せにせず、意図した位置で改行されるようにする
  （`word-break: keep-all` を適用）
- 筆のストロークの上に文字が乗る場合、コントラスト比を必ず確認する
- キーボードフォーカスが視認できること（`#2F3A8C`）
- `prefers-reduced-motion` を尊重
- 筆の SVG / 画像には `pointer-events: none` と `aria-hidden="true"` を付ける
