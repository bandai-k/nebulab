# NRT LOFT サイトリニューアル 作業指示書

対象リポジトリ: `bandai-k/nrt-loft`
作成日: 2026-09-03

---

## 0. この作業の目的

NRT LOFT を「木と革の名入れ工房・ショップ」から、**AIで自分のためのものを作る活動を発信するメディア**へ作り替える。

ブランドの定義は次のとおり。

- NRT LOFT = 成田・花崎町にある場所の名前であり、同時にそこで行われている活動の名前
- **場所としての機能（工房・ショップ・受注・来訪）は今回すべて停止する**
- 木と革の名入れ商品は NRT LOFT の外に出す。サイトからは一切触れない
- コワーキングという表現は使わない
- 運営主体は Nebulab合同会社。個人プロジェクトとは書かない

読者は**非エンジニア**。「プログラミングを学ぼう」でも「AIで稼ごう」でもなく、
**欲しいものがなければ自分で作る**という使い方を伝えるサイトにする。

---

## 1. 進め方

以下のフェーズ順に進め、**各フェーズごとにコミットを分ける**。
特に Phase 1（掃除）は他の変更と混ぜないこと。差分が読めなくなる。

Phase 0 調査 → 1 掃除 → 2 MDX基盤 → 3 ルート再編 → 4 トップページ → 5 記事ページ → 6 メタ・配信

各フェーズの終わりに `npm run build` が通ることを確認する。

---

## 2. Phase 0 — 調査（コードを書く前に必ず実施）

まず現状を把握し、**着手前に以下を報告すること**。

1. `src/` のディレクトリ構成とルート一覧
2. `src/app/layout.tsx` — フォントの読み込み方法、メタデータの定義方法
3. `globals.css` の `@theme` 定義（Tailwind v4 のため設定は CSS 側にあるはず）
4. ヘッダー / フッターがコンポーネントとして切り出されているか、ページ内に直書きか
5. コンタクトフォームと Resend の API ルートの場所と実装
6. `public/` 配下の画像ファイル一覧
7. framer-motion がどこで何に使われているか

調査結果を踏まえて、**実際の作業計画を提示してから**着手する。
この指示書の想定と実態が食い違う場合は、実態を優先し、食い違いを指摘すること。

このフェーズは**削除のみ**のコミットにする。

## 4. Phase 2 — MDX 基盤

記事は**リポジトリ内の MDX** で管理する。CMS は使わない。

### 導入するもの

- `@next/mdx`（または `next-mdx-remote`。既存構成に馴染むほうを選び、理由を述べること）
- frontmatter パーサ（`gray-matter` 等）
- シンタックスハイライト（`rehype-pretty-code` 等）
- `next.config.ts` に `pageExtensions` とリダイレクトを追記（現在ほぼ空）

### 記事の置き場所

```
content/
  build/     … 作ったものの記録（サイトの中心）
  learn/     … 作って分かったこと、失敗、AIとの付き合い方
  toolkit/   … 道具、プロンプト、開発環境、AI料金プラン
  journey/   … 活動そのものの記録、数字、裏側
```

### frontmatter の型

```yaml
---
title: "学校のプリントが処理しきれないので、撮るだけで予定になるツールを作った"
description: "提出期限・持ち物・行事を自動で整理して、カレンダーにも登録する"
category: build          # build | learn | toolkit | journey
date: 2026-09-10
updated: 2026-09-12      # 任意
cover: /images/build-04.jpg
tags: ["OCR", "カレンダー連携", "Claude Code", "Next.js"]
tools: ["Claude Code"]   # 任意。使用したAI
youtube: "xxxxxxxxxxx"   # 任意。動画ID
draft: false
---
```

型定義を `src/lib/` あたりに置き、記事の読み込み・一覧取得・カテゴリ絞り込みを行うユーティリティを作る。
`draft: true` の記事は本番ビルドから除外する。

## 6. Phase 4 — トップページ

上から順に次の構成。**セクション見出しに `01 ·` のような通し番号は付けない**（順序に意味がないため）。

### 6.1 ヘッダー

左にロゴ（`NRT LOFT` とタグライン `OPEN FLOOR, OPEN MIND`）、
右にナビ（BUILD / LEARN / TOOLKIT / JOURNEY / ABOUT）、YouTube と RSS のアイコン、
そして CTA ボタン「制作記録を見る」。

CTA の文言はサイト全体で**「制作記録」で統一**する。「記事を見る」と混在させない。

### 6.2 ヒーロー

左にテキスト、右に画像の2カラム。

**小見出し（アイキャッチ上の英字ラベル）は置かない。** 見出しから始める。
以前の案にあった `NARITA, CHIBA / AI BUILD LOG` は削除済み。地名は出さない。

見出し（2行、手書き系フォント、2行目に黄色のマーカー下線）:

```
欲しいものが無かったので、
自分で作ることにした。
```

本文:

```
コードが書けなくても、AIと一緒なら
「自分の困りごとを解決する小さな仕組み」は作れます。
その過程を、そのまま公開しています。
```

ボタン2つ:
- 主: 「最新の制作記録を見る」→ `/build`
- 副: 「YouTubeで見る」→ YouTube チャンネル

**ヒーロー画像に関する重要な制約:**
**コードが映っている画面を使わないこと。** 非エンジニアが最初に見る画面に
黒いエディタ画面があると、伝えたいことと正反対の印象になる。
プリントの束、冷蔵庫のメモ、手書きの走り書き、机の上の日用品など、生活側のものを使う。
木のデスク・窓の光・観葉植物といった雰囲気はそのまま活かしてよい。
画像が用意できるまでは、指定サイズのプレースホルダを置いておく。

### 6.3 LATEST BUILD

非対称レイアウト。左に最新1本を大きく（カバー画像・カテゴリ・タイトル・説明・タグ・リンク）、
右に過去3本をサムネ付きの縦リスト。右下に「すべての制作記録を見る」。

記事が1本しかない段階でも崩れないこと。0本のときは何を出すかも決めておく。

### 6.4 TOOLS

`Claude Code` と `Codex` のチップを横並びで置く小さな帯。
**ヒーローには置かない。** 制作記録の直後に置く。
実物を見せたあとに道具を明かす順序にすることで、技術を主役にしない方針と整合する。

### 6.5 CATEGORY

BUILD / LEARN / TOOLKIT / JOURNEY の4つ。それぞれアイコン、名前、1〜2行の説明。

```
BUILD    実際に何かを作る記録。小さな仕組みをひとつずつ。
LEARN    作って分かったことや失敗、AIとの付き合い方。
TOOLKIT  使っている道具やプロンプト、AI料金プラン。
JOURNEY  この活動自体の記録と、試行錯誤のプロセス。
```

BUILD が中心で他が補助、という関係が視覚的に分かるとよい。

### 6.6 最新の記事 / ABOUT

左右2カラム。

左は最新記事リスト（日付・カテゴリ・タイトル）。
**「NEWS」ではない。** お知らせ機能は作らない。BUILD 以外のカテゴリの記事がここに入る。

右は NRT LOFT の紹介。

```
NRT LOFT は、成田の旧釣具屋2階にある小さな場所の名前です。
欲しい場所が無かったので、自分たちの手で作り直しました。
ここでやっていることも、結局は同じです。
```

その下に「運営：Nebulab合同会社（代表 萬代晃生）」。

### 6.7 NEBULAB への導線

フッター直前に1バンド。

```
本格的に開発したい方へ
システム・サービス開発のご相談は NEBULAB へ
[ NEBULAB を見る ]  → https://www.nebulab.jp/
```

### 6.8 フッター

ロゴ、ABOUT / CONTACT / PRIVACY / 運営者情報、`© 2026 Nebulab合同会社`。

`© NRT LOFT` とは書かない。運営主体は法人。

## 7. Phase 5 — 記事ページ

### 一覧ページ（`/build` 等）

カテゴリ名と説明、記事カードのグリッド。件数が少ないうちも成立するレイアウトにする。

### 詳細ページ（`/build/[slug]`）

必要な要素:

- タイトル、日付、カテゴリ、タグ
- カバー画像
- 本文（見出し・コードブロック・画像・引用・リスト）
- YouTube 埋め込み（frontmatter に `youtube` があるとき）
- 目次（長い記事が多くなる想定なので付ける）
- 前後の記事へのリンク
- 記事末に NEBULAB への導線を1行

**本文の読みやすさを最優先にする。** 記事が主役のサイトなので、
行長は全角40字程度、行間はゆったり取る。コードブロックは長い引用が入る前提で組む。

プロンプトを載せる機会が多いので、**コピーボタン付きのコードブロック**を用意する。

## 8. Phase 6 — メタデータと配信

- 各ページの `title` / `description` を設定
- **サイトの `title` は `NRT LOFT｜AIで自分のための道具をつくる`**（ヒーローに説明ラベルを置かない分、ここで補う）
- 既存のメタから工房・ショップ関連のキーワードをすべて削除
  （`成田 名入れ` `成田 ノベルティ` `成田 記念品` `成田 ハンドメイド` `漢字 木札` など）
- OGP 画像の差し替え。現在の `og-image.png` は工房のもの。記事ごとの OGP も生成できるとよい
- RSS フィードの生成（ヘッダーに RSS アイコンを置くため）
- `sitemap.xml` と `robots.txt`
- 構造化データ（記事ページに `Article`）

## 9. デザイン仕様

### 配色

紙に近いライトテーマ。**ダークテーマは実装しない。**

| 用途 | 値 |
|---|---|
| 背景（基本） | `#FFFFFF` |
| 背景（セクション交互） | `#F7F6F1` |
| 面（カード・プレースホルダ） | `#F1EFE8` |
| 罫線 | `#E4E2DB` / 強め `#D3D1C7` |
| 本文 | `#2C2C2A`（真っ黒にしない） |
| 補助テキスト | `#5F5E5A` |
| 淡いテキスト | `#888780` |
| マーカー・アクセント | `#FAEEDA` |

差し色はカテゴリのアイコン背景とマーカーのみ。それ以外は無彩色で通す。

### タイポグラフィ

- 見出し: 手書き系・丸みのある日本語フォント。硬いゴシックや等幅は使わない
- 本文: 可読性重視の日本語フォント
- 2書体まで。役割を明確に分ける
- **英字ラベルを装飾として増やさない。** ナビとカテゴリ名以外に英字の小見出しを足さない

### トーン

見出しは話し言葉で書く。「〜を実装しました」ではなく「〜を作った」。
専門用語をタイトルに出さない。困りごとから書く。

### 品質基準

- モバイル対応必須。読者はスマホで読む
- キーボードフォーカスが見えること
- `prefers-reduced-motion` を尊重する
- framer-motion は既存で使われているが、**各セクションのフェードインを機械的に付けない**。
  動かすなら1箇所に絞る
